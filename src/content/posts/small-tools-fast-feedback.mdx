---
title: Small tools, fast feedback
description: A short note on why I like boring infrastructure and sharp local tooling.
date: June 6, 2026
---

I keep coming back to the same kind of software: small tools that make the boring path faster.

The useful part is rarely the size of the tool. It is the feedback loop around it. A parser that gives a clear error, a formatter that settles arguments, a build step that fails quickly, or a package that removes one repeated decision from every project.

That is the kind of infrastructure I like maintaining. It should be quiet when things work, precise when they do not, and cheap enough to run constantly.

:::note[Good default]
The best tools usually disappear into the workflow after the first setup.
:::

```ts
export function isUsefulTool(runTimeMs: number, surpriseCount: number) {
  return runTimeMs < 1000 && surpriseCount === 0;
}
```

> [!TIP]
> Keep the slow path visible, but make the common path boring.

Not every tool needs a platform around it. Sometimes the right shape is just a package with a narrow job and a README that tells the truth.
